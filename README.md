# LR6
## Лабораторная работа №6  
## Система контроля версий

 ### **1. Цель работы**  
Целью работы является изучение базовых возможностей системы управления версиями, опыт работы с Git Api, опыт работы с локальным и
удаленным репозиторием.
### **2. Задачи**
1. Создать аккаунт на сайте GitHub.
2. Сделать копию в личное хранилище из
https://github.com/Kurtyanik/LR6/ (Fork).
3. Установить Git (https://git-scm.com/).
4. После установки настроить клиент git, введя имя пользователя (Группа
Фамилия И.О.) и email.
5. Клонировать свой личный удалённый репозиторий на компьютер.
6. Добавить файл через интерфейс GitHub. Подтянуть изменения в
локальный репозиторий.
7. Получить историю операций для каждой из веток.
8. Просмотреть последние изменения.
9. Выполнить слияние в ветку master, разрешив конфликт (можно
использовать специальные редакторы или графический интерфейс git).
10. Удалить побочную ветку после успешного слияния.
11. Сделать изменения и зафиксировать их, оставляя комментарии,
несколько раз.
12. Сделать откат коммита.
13. Создать ветку для отчёта. 
14. Начать оформлять отчёт в файле README.md (разрешены сторонние
редакторы с подсветкой синтаксиса), используя markdown синтаксис
(https://guides.github.com/features/mastering-markdown/):
(В отчёте должен быть снимки экрана консоли и сторонних программ).
15. Файлы снимков экрана разместить в отдельной папке.
16. Получить историю операций в форматированном виде (сокращённый
хэш + дата + имя автора + комментарий). Добавить её в отчёт и сделать
финальную фиксацию изменений.
17. Отправить локальные изменения в сетевое хранилище GitHub (если
делаете работу постепенно, то синхронизацию проводить в конце рабочего
сеанса)
### **3. Ход работы**  
3.1 До выполнения работы аккаунты в GitHub и git уже были зарегестрированы. Клонирование удаленного репозитория
в локальное хранилище осуществляется через систему контроля версий через команду `git clone` ([рис.1](https://github.com/Samsa-masa/LR6/blob/6c39b1cf4aec4e3cb89a1f1e2872e21773b01e88/Pictures/%D0%BB%D0%BE%D0%B31.png)).
Сменить информацию о пользователе под требуемый формат в конкретном репозитории можно через `git config user.name` 
и `git config.email`.  

3.2 Чтобы синхронизировать удаленный и локальный репозитории после создания через интерфейс GitHub файла File_hello
в командной строке пишется `git pull` ([рис.2](https://github.com/Samsa-masa/LR6/blob/6c39b1cf4aec4e3cb89a1f1e2872e21773b01e88/Pictures/%D0%BB%D0%BE%D0%B32.png)).  

3.3 Получить историю изменений можно через `git log`, коммиты будут отображаться от последнего к первому ([рис.3](https://github.com/Samsa-masa/LR6/blob/6c39b1cf4aec4e3cb89a1f1e2872e21773b01e88/Pictures/%D0%BB%D0%BE%D0%B33.png), 
[рис.4](https://github.com/Samsa-masa/LR6/blob/6c39b1cf4aec4e3cb89a1f1e2872e21773b01e88/Pictures/%D0%BB%D0%BE%D0%B34.png)),
с указанием автора, хэша и даты изменений. Вывод можно форматировать разными модификаторами: `--oneline`, `--graph`, `--all` и др. 

3.4 Создать ветку remaster для слияния через git можно командой `git branch`([рис.5](https://github.com/Samsa-masa/LR6/blob/6c39b1cf4aec4e3cb89a1f1e2872e21773b01e88/Pictures/%D0%BB%D0%BE%D0%B35.png));
`git checkout`может перемещать на нужный коммит/ветку([рис.6](https://github.com/Samsa-masa/LR6/blob/6c39b1cf4aec4e3cb89a1f1e2872e21773b01e88/Pictures/%D0%BB%D0%BE%D0%B36.png)).
Через строку был создан файл file_bie и обе ветки были слиты в master ([рис.7](https://github.com/Samsa-masa/LR6/blob/6c39b1cf4aec4e3cb89a1f1e2872e21773b01e88/Pictures/%D0%BB%D0%BE%D0%B37.png)).
Затем с помощью `git branch -d` ветка remaster была удалена.  

3.5 Для отправки изменений из локального репозитория в удаленный нужные изменения из файлов сохраняются в индекс `git add` , затем
исходя из данных в индексе создается коммит `git commit` и отправляется в удаленный репозиторий `git push` ([рис.8](https://github.com/Samsa-masa/LR6/blob/6c39b1cf4aec4e3cb89a1f1e2872e21773b01e88/Pictures/%D0%BB%D0%BE%D0%B38.png)).  

3.6 В последних двух созданных файлах дважды добавлялось по строке текста, соответственно изменения дважды коммитились ([рис.9](https://github.com/Samsa-masa/LR6/blob/6c39b1cf4aec4e3cb89a1f1e2872e21773b01e88/Pictures/%D0%BB%D0%BE%D0%B39.png),
[рис.10](https://github.com/Samsa-masa/LR6/blob/6c39b1cf4aec4e3cb89a1f1e2872e21773b01e88/Pictures/%D0%BB%D0%BE%D0%B310.png)).
Чтобы откатить последний коммит (в каждом файле станет по две строки, а не три)
поможет команда `git reset --hard HEAD~1`([рис.11](https://github.com/Samsa-masa/LR6/blob/6c39b1cf4aec4e3cb89a1f1e2872e21773b01e88/Pictures/%D0%BB%D0%BE%D0%B311.png)).

3.7 Для написания отчета в файле README.md была создана отдельная ветка report. Для оформления использовалась программа 
Visual Studio c расширением *Markdown Editor v2*.

### Выводы
В ходе работы были получены базовые навыки работы с системой контроля версий, локальным и удаленным репозиториями.
